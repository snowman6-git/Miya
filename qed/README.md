# qed/ — Quasi-Evolutionary Diary

**한국어** | [English](README.en.md)

행동과 결과를 기록해 두고, 다음 판단 때 경험으로 주입합니다. DB(`data/qed.db`)는 공개하지 않고 스키마만 올립니다.

| 표 | 내용 |
|---|---|
| `goals` | GOAL 1회: 요청, 목표, 개수, 방법(via), 성공, 소요 ms, 실패 사유, 모델 입력 ctx, 변수(보유 도구·장비·시간) |
| `steps` | GOAL의 단계별 type·target·cnt·도구·ms·성공·실패 사유 |
| `deaths` | 사망: 원인, 가해자, 체력·배고픔·밤·방어·무기, 위치, 인벤과 그 가치, 진행중이던 GOAL |
| `placed` | 봇이 설치한 블럭 (작업대·화로·상자 재사용, 남의 상자와 구분) |

`serve.py`가 시작할 때 테이블을 직접 만듭니다. `schema.sql`은 참고용입니다.

## 경험 주입 방식 (`serve.py` `qed_of`)

1. 같은 goal에서 방법 경로(`via:` 토큰)가 같은 최근 20건을 모읍니다.
   - 제외: 유저 멈춤·선점(`stopped`), 봇 버그(`craft_unsynced`)
   - 작업 중 사망한 건은 실패로 셉니다.
2. 방법 보기 텍스트 뒤에 `경험 N회 성공 X% 평균 T초 최근실패 K회(사유)`를 붙입니다.
3. 경험을 뺀 상태로 한 번 더 선택해 봅니다. 결과가 다르면 `changed`로 표시합니다(경험이 판단을 바꿨다는 뜻).
