# Miya 개요 (다이어그램·문서용 단일 참조) — 2026-09-29, Miya-0.2 기준

마인크래프트 AI. 한국어 명령을 **모델이 전부 판단**하고, 봇은 모델이 못하는 실행(걷기·캐기·클릭)만 함.
참고 그림: `docs/miya_infographic.svg` (영문 `.en.svg`, 생성기 `docs/infographic.py`, `LANG_OUT=en`)

## 1. 한 줄 구조

```
플레이어 채팅 ─▶ Paper 서버 ─▶ 봇(TS·mineflayer) ─HTTP JSON─▶ 모델 서빙(Python :8765) ─▶ Miya 모델 + planner + mcx.db + QED DB
                                   │  ▲ 스텝 배열·판단 결과                       ▲
                                   │  └──────────────────────────────────────┘
                                   ├─▶ 실행 결과 /qed → QED DB (경험 누적 → 다음 판단에 주입)
                                   └─▶ 웹 API :8090 ─▶ WEBUI (상태·진행 애니메이션·설정)
로그(서버 채팅·봇 로그) ─▶ 학습 데이터 ─▶ 학습(GPU) ─▶ 평가 ─▶ 인게임 실측 ─▶ 새 버전
```

## 3. 모델 (Miya-0.2)

- 인코더: mmBERT 22층, bf16. vocab 256,000→29,252 가지치기, 파라미터 312M→139M, ckpt 292MB
- 방식: GLiNER2식 — 입력 = 스키마(질문+보기) + 문장 + 상태 ctx → **1회 인코딩으로 여러 출력**
- 지연: 턴 p50 17.8ms / p95 19.7ms (RTX, 단일 요청)

| 헤드 | 출력 |
|---|---|
| 보기 점수 ([MASK] scorer) | act(11) · task_type(39) · query(18) · hint(5) · prio(9) · 방법(via) · tidy(3) |
| 구간 추출 | 대상·개수·도구·사람·좌표·장소·거리 (7종, 폭≤8) |
| 아이템 링크 | 구간 ↔ 아이템 bank 1,628개. bi-encoder + ColBERT(토큰 late-interaction). NULL=모름→되묻기 |
| 짝(GLiREL식) | 개수 ↔ 대상/도구 연결 |
| 가치 | 방법별 [예상 소요시간, 성공확률] |
| 숫자 MLP | 체력·거리 등 수치 특징 |

라벨 목록
- act: 목표 실행, 질문 답하기, 되묻기, 멈춤, 재개, 긍정, 부정, 잡담, 욕설, 위험 경고, 지적·조언
- prio(생존): 계속 진행, 근접 전투, 달려서 도망, 블럭 쌓아 도망, 굴 파고 숨기, 먹기, 멈춘 작업 재개, 물 위로 올라가기, 인벤 정리
- hint(지적): slow 느림 / wrong 틀림 / short 부족 / danger 위험 / done_claim 했다더니 안됨
- task_type: 제작·채광·벌목·삽질·농사·굽기·사냥·전투·양동이·정리·꺼내기·주기·버리기·장착·먹기·설치·회수·오기·따라가기·이동·줍기·숨기·자기·도망·블럭쌓기·굴파기·지키기·자율·건축·인챈트·낚시·거래·원거리·보트·마인카트·확인·상대이동·장소지정 (39)

## 5. 봇 루프 (main.ts)

1. **채팅**: 프리픽스 호출 → /turn → act 분기 (목표 실행이면 runGoal, 질문이면 답변, 모름이면 되묻기 → 답변까지 합쳐 멀티턴 재인식)
2. **생존 틱**: `prio_ms`(기본 1s)마다, 상태 시그니처 변할 때만 /prio. 전투/도망 결정 후 `prio_hold_ms` 유지(루프 방지). 사용자 강제 규칙(hp_flee, hp_eat, hostile_policy) 우선
3. **GOAL 실행 (runGoal)**: /plan → 스텝 배열 순차 실행 → 일시 실패는 스텝 재시도(≤3), 영구 실패는 재계획(QED 최근 실패 반영, 상한) → 완료 인지 후 보고
   - 스텝 종류: gather(채집/채광/벌목), stair(계단굴), craft, furnace, place, hunt, expedition(원정: 범위내 대상 없음), tidy
   - 설치물 기억: 작업대·화로 위치 저장 → 재사용 (중복 제작 방지), 가보니 없으면 forget
4. **결과 기록**: /qed (스텝별 도구·소요ms·성패·변수), 사망시 /death
5. **이벤트**: decision / step / crafted / smelted / step-fail / evade / say → /events (WEBUI 애니메이션)

## 6. GOAL 예시 흐름 ("금 2개 캐와")

```
/turn  → act=목표 실행, type=mine, 대상=grp:gold, 개수=2
/plan  → planner 후보: [돌곡 경유] [철곡 경유] … (각 후보에 예상시간·위험·QED 경험 텍스트)
         모델이 선택 (via:iron_pickaxe), ore_y → 금 목표 y=-16
스텝   → 작업대 설치(재사용) → 화로 설치 → 돌곡 제작 → 철 3 채광 → 철 굽기 → 막대기 → 철곡 제작
         → 원정(범위 확인) → 계단굴 y11→-16 (싼 곡괭이 소모) → 금 2 채광 (철곡)
실패   → 곡괭이 파손 = no_tool → 재계획 → 곡괭이 재제작
기록   → /qed: 방법·스텝별 ms·성패 → 다음 "금 캐와"에서 이 경험이 보기 텍스트로 주입
```

## 7. QED (Quasi-Evolutionary Diary, 준진화 경험 DB) — 핵심 기능

목적: 실제 플레이 경험을 축적 → 다음 같은 GOAL에서 검증된 방법을 고르게 함 (재귀적 자기개선, 향후 자율모드에서 RL식 루프)

- **기록 (qed.db)**
  - goals: 요청·GOAL·개수·방법(via)·성공·소요ms·실패사유·ctx·변수(보유 도구 티어·장비·시간 등)
  - steps: GOAL별 스텝 i·타입·대상·개수·도구·ms·성패
  - deaths: 원인·가해자·체력·배고픔·밤·장비·위치·인벤·인벤 가치·복구/개선
  - placed: 내 설치물 좌표
- **조회·주입**
  - 같은 GOAL + 같은 방법 핵심(core = via: 경로) 최근 20건 → "경험 N회 성공 X% 평균 Y초 (최근 연속실패 K)"
  - 이 텍스트가 /plan 보기에 붙음 → **모델이 읽고** 선택 (규칙 아님)
  - 반복 실패 방법 차단, 사망원인 → prio ctx "최근 사망원인"
  - 아이템 가치 = 기본(재료·희귀도) + 경험 보정 (얻기 힘들수록 가치↑ → 사망 후 회수 판단)
- **발현 표기**: 경험을 빼고 한번 더 선택 → 결과 다르면 `qed.changed=true`, `base → via` (웹 이벤트·로그 "QED 바꿈")
- 한계(0.3 예정): 경험이 같은 방법끼리도 changed 표기됨

## 10. 설계 원칙 (그림에 강조할 것)

- 판단 = 모델, 봇 = 실행기 (정규식·조건문 판단 금지)
- 사실 계산(레시피·광석 높이)은 planner, **선택**은 모델
- 가벼움·속도: 1회 인코딩 다중 출력, 턴 ~18ms
- 경험 → 판단 개선 (QED), 무한루프 차단(재시도·재개 상한, 판단 유지시간)
- 향후: Rust 서빙·봇, 자율모드(생존·발전 자동, QED 보상 루프)
